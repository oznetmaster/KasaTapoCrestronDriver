# Customer outlet diagnostic build 2.1.014.0002

This reserved customer-only build investigates telemetry notification volume and TPAP connection failures reported through an orphaned Home service. It retains 2.1.014.0001 control, 0.1 V voltage rounding, other telemetry precision, polling intervals and startup/event behavior.

Build in Release with `-p:OutletDiagnosticBuild=true`. This defines OUTLET_DIAGNOSTICS independently of DEBUG. Normal Release builds compile out capture calls and omit the journal/record types. Do not enable general debug logging to obtain this capture.

The typed JSON Lines records contain UTC and monotonic timestamps, a process capture session and per-entity instance ID, controller ID/name/model, local host/port, transport/family/encryption/login version, lifecycle flags, numeric comparison decisions, actual property-publication context, raw and published energy readings, refresh duration and classified connection errors. No protocol payload, credentials, authentication token or full exception message is captured. Stack frames are retained. Reports contain private household names and LAN addresses; send them privately to support.

Capture is automatic for at most 30 minutes after the journal is first used, with a maximum 2 MiB active file and one retained previous file (4 MiB total). A bounded 512-record queue keeps disk I/O off refresh/control threads. A size limit or I/O failure disables capture; it does not change device control. Queue drops are counted in subsequent records. A process restart can start a new bounded capture; an entity-only reload may share the current process/session and its remaining capture window. All records carry independent outlet instance IDs.

Fixed processor folder: `/user/Data/ThirdParty/NeilColvin/KasaTapoCrestronDriver/outlet-diagnostics-2.1.014.0002/`. Only `capture.jsonl` and `previous.jsonl` are collected. The Windows uploader built with `tools/Build-TestSideload.ps1 -OutletDiagnosticBuild` adds Collect diagnostics. It confirms SSH identity, reads only those bounded files, creates a local ZIP and never changes processor files while collecting. It does not collect system configuration, credentials or the full Home log.

Customer run: upload, then update the existing platform in Home Setup/Configure Pro. Keep polling and feedback programming. Leave driver logging unchecked. Collect after 5–10 minutes of normal plug use; include a driver reload within that interval if practical to observe old/new instance lifecycle. Do not remove/re-add children or reboot the whole processor for this test. Collection needs the processor login again because credentials are not saved.

Read the capture alongside Home's timestamps. Numeric decisions record the prior entity value, candidate (voltage already rounded) and change decision; `published:` records identify successful property notifications and distinguish full startup snapshots from comparisons. Raw/published samples use the typed client model. A TPAP failure record maps the error to a named instance and selected endpoint/protocol; Stopped/Disposed/Generation and adjacent lifecycle records show whether it belongs to a replaced instance. This evidence can identify the failing path but does not by itself prove device firmware defects or processor load capacity. No additional network polls or power commands are introduced.

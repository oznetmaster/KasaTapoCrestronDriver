# Standalone outlet polling candidate 2.1.014.0003

The customer test build preserves the platform's configured light/outlet interval (10 s on the test installation), publishes confirmed command feedback without waiting for a poll, and refreshes energy and other full-state modules only once a minute on standalone outlets. It does not change voltage precision. A common monotonic clock spreads 20 physical slots across the interval, with a per-platform cap of three background outlet operations. Direct commands bypass the shared cap and serialize only with operations for their own outlet/strip. One legacy strip read serves its registered sockets; SMART strips retain their existing full child refresh for compatibility. Hubs and native lights retain their separate pollers.

When a standalone outlet connects, the observed device ID must match both the descriptor and cache entry before verified reconnect settings can replace the cached protocol. Device names, controller IDs, configuration and placement are preserved. Discovery remains authoritative for trying fresh protocol metadata; there is no model-specific KLAP override.

The candidate branch uses the frozen local package `KasaTapoClient.2.0.1-outletpoll.2.nupkg` (SHA-256 `b5d058bb5974a4d7eb7dfbb9f788b776e9d830f9e62b23ceb6d284bfd8c39aca`), built from the previous shipped client baseline f45444996d48ded8314a2f5b86792b473bbab30a plus the typed outlet API patch at client commit 3078b54. Restore candidate builds with its private feed in RestoreAdditionalProjectSources. It is merged into the customer driver; no separate client install or NuGet publication is required. Public release branches should use a published client version containing the typed API before merging this candidate.

Validation: 136 client checks on each runtime, 158 desktop lifecycle checks, 34 portable and 34 ordinary processor checks passed. The 132-second mixed run used the real KP115 and KP303 socket plus 18 loopback legacy TCP simulators on both workstation and processor. On the processor: 264 successful reads, 10064 ms longest read gap, 38 standalone energy refreshes, at most one scheduled start in a 100 ms window, and 143 ms confirmed simulator command with all three background permits occupied. No real power commands or processor reboot. The CPU observation (4260 ms over the window) includes the processor process and loopback simulation; it is not an isolated measurement of driver CPU or a qualification for 20 KLAP devices.
